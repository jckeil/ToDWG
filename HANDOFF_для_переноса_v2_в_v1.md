# HANDOFF — перенос знаний ToDWG v2.x (для агента, который знает только v1)

Этот файл описывает ВСЁ, что изменилось в версии 2 относительно v1, с причинами
и следствиями. Читать целиком перед первым изменением кода v2.

## 0. Что это и откуда

- **ToDWG v2.x** — форк от **v1.7/v1.8-dev** (репозиторий `jckeil/ToDWG`).
  Работа ведётся в **отдельном репозитории `jckeil/ToDWG2`** (не форк GitHub, а
  новый репозиторий с перенесённой историей). Линия 1.x не трогается.
- Основной файл по-прежнему **монолит `ToDWG_v2.py`** (те же 6 блоков, что в v1),
  сборка — `ToDWG_v2.spec`, exe — `ToDWG_v2.x-beta.exe`.
- Версия: выпущена **v2.0 (beta)**; в разработке **v2.1 (beta)**. Суффикс
  **«(beta)» приписывается всегда**, пока не объявлен публичный релиз.
- Git: ветка `main`; `origin` → `jckeil/ToDWG2`, `upstream` → `jckeil/ToDWG`.
  Тег `v2.0-beta` → коммит `edd5e9e`; `main` на начало v2.1 = `b21c593`.
  GitHub Release `v2.0-beta` (prerelease) с exe-ассетом.

## 1. Ключевые константы и модель версии

| Было в v1 | Стало в v2 |
|---|---|
| `APP_VERSION = "v1.8"` | `APP_VERSION = "2.1"`, `APP_STAGE = "beta"`, `APP_DISPLAY_VERSION = f"v{APP_VERSION} ({APP_STAGE})"` |
| `APP_FULL_TITLE = f"{APP_NAME} {APP_VERSION} — …"` | использует `APP_DISPLAY_VERSION` → «ToDWG v2.1 (beta) — …» |
| `APP_USER_MODEL_ID = "ToDWG.App.V1"` | `"ToDWG.App.V2"` |

Причина: отдельная линия 2.x + явный признак beta. Следствие: везде, где версия
показывается пользователю (заголовок окна, нижняя подпись, лог, `parse_args`),
используется `APP_DISPLAY_VERSION`; в `result.json` версия остаётся машинной
(`APP_VERSION`). `tests/_gui_selftest.py` сравнивает подпись с
`APP_DISPLAY_VERSION`.

## 2. Хронология изменений v2 (причина → следствие)

### 2.1 Форк и переименование
- `ToDWG_v1.py` → `ToDWG_v2.py`, `ToDWG_v1.spec` → `ToDWG_v2.spec`; exe сначала
  `ToDWG_v2.0-beta.exe`, затем `ToDWG_v2.1-beta`.
- Тесты импортируют `ToDWG_v2`; `_test_exe_gui.py` ищет `dist\ToDWG_v2.0-beta.exe`,
  заголовок `ToDWG v2.`.

### 2.2 Задача 2 — проверки сетевых папок
- Константа `NET_PROBE_TIMEOUT = 5.0`.
- Новая `probe_path(path, timeout=5.0, need_write=True) -> (ok, error)`:
  проверка в **фоновом потоке** с `join(timeout)`; проверяет `exists` → `isdir` →
  `os.listdir` → пробную запись/удаление `.ToDWG_probe_*.tmp`.
- Причина: обращение к «мёртвому» UNC-серверу в диалогах Windows вешает GUI;
  раньше сетевые папки просто запрещались.
- Следствие: сетевые (UNC) папки разрешены, но перед использованием проверяются;
  при недоступности — понятная ошибка + запись в лог; GUI не зависает.

### 2.3 Задача 3 — рекурсивная конвертация папки
- `find_sdd_recursive(root)` — `os.walk`, сортировка по путям.
- `unique_path(dir, stem, ext)` — `имя.ext`, `имя (2).ext`, `(3)`…
- `relocate_result(stats, target_dir)` — переносит готовый DWG/DXF из
  `stats["target"]` в целевую папку (`shutil.move`, fallback `copy2`).
- Кнопка **«Обработать папку…»**; `folder_worker`/`start_folder_work` (временная
  папка `tempfile.mkdtemp` → `run_pipeline` → `relocate_result` → удалить temp).
- Причина: массовая конвертация с результатом рядом с исходником и без
  «размножения» версий файлов.
- Следствие: результат по умолчанию кладётся **рядом с каждым `.sdd`**, коллизии
  имён решаются суффиксами `(2)`, `(3)`…

### 2.4 Смена поведения «Обработать папку…»
- Было: выбор папки → сразу «Найдено N, продолжить?» → автозапуск.
- Стало: сканирование → найденные `.sdd` **добавляются в список очереди** (без
  автозапуска) → окно-отчёт с одной кнопкой ОК → возврат в главное окно.
- Причина: дать пользователю исключить лишние файлы (крестиком) до запуска.
- Следствие: блокировка ручных листов/формата через существующий
  `sync_bulk_controls()` по числу файлов; конвертация — только кнопкой
  «Конвертировать».

### 2.5 Унификация сохранения: «рядом с исходником» для всех
- Убран прежний путь `worker()/start_work()` (папки `<имя>_<дата>` под папкой
  результата). Всё идёт через **один** `folder_worker(paths, manual_folder,
  result_dir, manual_count, paper_w, paper_h)`:
  - галочка «Выбрать папку для готовых файлов» выключена →
    `target_dir = os.path.dirname(source)`;
  - включена → `target_dir = out_state["dir"]` (общая папка).
- `manual_count` и `paper_w/h` (A2/A3/A4) пробрасываются для одиночного файла.
- Причина/следствие: у каждого файла «свой путь»; одиночная конвертация больше
  не создаёт папку `<имя>_<дата>`, а кладёт `имя.dwg` рядом с `.sdd`.

### 2.6 Строка «Сохранить в:» и галочка
- Метка «Папка результата:» → **«Сохранить в:»**.
- Галочка переименована: «Выбрать папку вручную» → **«Выбрать папку для готовых
  файлов»**.
- Галочка **только включает строку** (активная/неактивная); **не открывает**
  диалог. Диалог открывается кнопкой **«Изменить…»** и **стартует из папки
  первого исходного файла** (`on_choose_out_dir` смотрит `pending[0]`).
- При снятой галочке строка всегда показывает **«Рядом с исходным файлом»**
  (приглушённо, неактивно) — без «морганий» пути.
- `sync_outdir_row()` управляет состоянием; цвета — по теме (активная `#E6E6E6`,
  неактивная `#6E6E6E` в тёмной; `WIN11_TEXT`/`#9A9A9A` в светлой).
- Путь усекается по ширине (`_ellipsize_text` — серединное «…», пересчёт по
  `<Configure>`); кнопка «Изменить…» фиксированной ширины (`width=10`).

### 2.7 Расширенные настройки главного окна
- В «Настройках» добавлена галочка **«Расширенные настройки главного окна»**
  (`advanced_main`, по умолчанию выключена, сохраняется в конфиге).
- Пока выключена — строки «Указать количество листов вручную» и «Выбрать формат
  листа вручную (beta)» **скрыты** (`opts` не запакован); при включении
  `apply_advanced_main(on)` пакует/прячет `opts` перед предупреждениями.
- Сообщение «Для нескольких файлов…» показывается только когда расширенные
  настройки включены.
- Причина: упростить главный экран для рядового пользователя.
- Следствие: `advanced_state = {"on": ...}`; конфиг-ключ `advanced_main`;
  окно «Настройки» увеличено по высоте.

### 2.8 Окно: динамика → фиксированный размер под расширенный режим
- Итог: `fit_main_window()` рассчитывает высоту карточки по содержимому,
  **временно показывая** скрытые `opts`, чтобы зарезервировать место под
  расширенный режим; `card.place_configure(height=…)` + `_center(root, w, h)`.
- Поля вокруг рабочей области — **равны 32 px со всех сторон**; зазор до версии
  мал (~9 px).
- Переключение расширенного режима **не ресайзит окно** (оно уже под
  расширенный) — иначе при включении текст уходил за границы.
- Причина: исправление бага «текст за границами при включении расширенных
  настроек»; окно не «прыгает».

### 2.9 Оформление/UX
- Кнопка «Обработать папку…» — **над** кнопками, на всю ширину, **серого**
  стиля, половинной высоты; «Добавить файлы»/«Конвертировать» — **равные**,
  зазор **40 px**, края по краям кнопки папки (единая ширина контента **460 px**,
  левый край 90).
- Кнопка «Выбрать файлы» → **«Добавить файлы»**.
- Подъём окна из панели задач: `_force_front()` по `<Map>` (topmost-toggle) +
  `lift()` по `<FocusIn>`; `back_to_main()` вызывает `_force_front()`.
- «Залипающие» подсказки убраны: очистка `hint_var` в `sync_bulk_controls`
  (ветка else), `start_*`, `back_to_main`.
- Предупреждения: `FONT_WARN` уменьшен 13 → **10 bold**; «НЕ ИСПОЛЬЗУЙТЕ
  КОМПЬЮТЕР ДО ОКОНЧАНИЯ КОНВЕРТАЦИИ» — **одна строка**; «ДЛЯ АВАРИЙНОЙ
  ОСТАНОВКИ НАЖМИТЕ \n CTRL+ALT+0» — «CTRL+ALT+0» **на отдельной строке**
  (явный перенос), обе вписываются в 460 px.

## 6. Известные проблемы и план (v2.1, ещё НЕ реализовано)

### 6.1 На чистом ПК нет ODA → нет DWG
- `find_oda()` ищет только `ODA_CONVERTER` и `C:\Program Files\ODA\…`. На чистом
  ПК ODA нет → `NoBackendError`, остаётся DXF.
- План: зашить портативный ODA File Converter в exe (PyInstaller `datas`) и при
  первом запуске копировать в `%LOCALAPPDATA%\ToDWG\oda\`; `find_oda()` искать и
  там. Требует подтверждения **лицензии ODA** и файлов ODA для сборки.
  Альтернатива (хуже) — автозагрузка MSI + `msiexec /qn` (нужен админ).
- Подготовлено (не внесено): расширенный `find_oda` (рядом с exe/ODA/oda) и
  улучшенное сообщение `NoBackendError` со ссылкой.

### 6.2 Без админ-прав не блокируется мышь и «застревает» после открытия Schemagee
- Причина: UIPI — Schemagee запущен **с повышенными правами**, а приложение без
  прав. Тогда `SendInput` не доходит (клавиши), а `WH_MOUSE_LL` не перехватывает
  события для окна более высокого уровня целостности (мышь). Оба симптома — это
  рассогласование прав, а не «нужен админ».
- Решение пользователю: запускать Schemagee **без прав администратора** (обычным
  двойным кликом); если Schemagee сам требует UAC — приложение тоже запускать от
  администратора.
- План кода: `_pid_is_elevated(pid)` (OpenProcessToken/TokenElevation через
  ctypes) + после открытия окна Schemagee: если приложение не elevated, а окно
  принадлежит elevated-процессу — бросать понятную `RuntimeError` (а не
  зависать). Подготовлено (не внесено).

## 7. Чек-лист перед изменением (наследуется из v1)
1. `python -m py_compile ToDWG_v2.py`
2. `python tests\_gui_selftest.py`
3. `python ToDWG_v2.py --headless --dxf-folder input --name check`
4. при изменении GUI — пересобрать exe и `tests\_test_exe_gui.py`
5. при изменении кликера — живой прогон `Примеры\…sdd`
6. не возвращать блокирующий `SendMessage`, не трогать хрупкие места кликера из
   v1 (раздел «Хрупкие места» старого HANDOFF остаётся актуальным).
